# Purpose

Enforces the cash-account rule. A SELL on a symbol with no held long
position would create a new short entry and is not permitted in a cash
account.

# Account policy (Jun, 2026-10-27)

* Short selling is not used. The only live target is the **cash account**
  (現物口座).
* The short path is retained solely for a future **margin account**
  (信用口座) and is enabled only by an explicit `ACCOUNT_TYPE=margin`.
* Fail-safe default (magi-core PR pending, `lib/account-type.js`): unset,
  empty or unrecognised `ACCOUNT_TYPE` resolves to `cash`. Before that change
  the code default was `margin`; every unit session has carried
  `ACCOUNT_TYPE=cash` since magi-core#631 (2026-10-19). The 2026-10-07 NKE
  840-share short (QWEN, sell 332723 / cover 332758) predates #631 and is a
  policy violation recorded in the [trades](/system/echidna-tables/trades.md)
  vocabulary notes.

# Behaviour

**Implementation update, pending independent review (2026-10-28):** the
[cash-first trading policy](trading-policy.md) checks fresh broker positions
and working orders in `src/llm.js`, before RECON, JEV and SHADOW recording.
A cash SELL must reduce an existing long after reserving working SELLs;
oversells and unverifiable exits are blocked with
`blocked_by: 'cash_account_guard'`. The LLM no longer has to call
`get_positions` to populate the session cache first. No margin mode is
enabled by a symbol's universe membership. See the new draft for the fixed
candidate boundary, evidence validation and reference revisions.

The prior implementation at magi-core `953637d` only checked the cached
`isHeldPosition()` boolean after the SHADOW branch. This draft update records
the proposed behavior; the historical human verification entry above does
not certify the new implementation.

# Constitution basis

[POSITION MANAGEMENT](/system/constitution/position-management.md): cash
accounts may only open with BUY and may SELL to close or reduce held longs.
