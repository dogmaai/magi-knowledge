# Purpose

Evaluates a provider/side combination for underperformance. **Currently
warn-only in the implementation** (`magi-core @ baa5388`,
`runL4Guard` in `src/paperGuards.js`): a below-threshold combo is logged and
journaled as a `WARN_ONLY` guard row for counterfactual measurement, but the
trade proceeds. The earlier design — a hard block backed by a `l4_probation`
state table — was never populated at runtime; that table is absent from
`magi_core` and its doc is deprecated. Whether warn-only becomes permanent or
the layer is re-promoted to blocking is a demotion decision pending
independent review (see [guards/index](/system/guards/index.md) and
magi-knowledge Issue #99).

# Implementation

`runL4Guard(ctx)` in `src/paperGuards.js` reads the in-session ISABEL stats
cache (`getIsabelStatsCache`) — no BigQuery state is read or written. It
flags a combo when `(wins + loses) >= 30 and win_rate <= 35` with
`loses >= 5`, or `(wins + loses) >= 10 and win_rate <= 30` with `loses >= 5`;
the warning is lifted when `recent_win_rate >= 50`. An exit on a held
position is exempt (the session position cache distinguishes opens from
exits).
